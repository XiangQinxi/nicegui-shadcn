nicegui-shadcn —— 工作原理

给 NiceGUI 的 shadcn/ui 组件：Python 工厂进，带样式的 Vue 组件出 —— 编译产物随包提交，使用者永远不需要执行任何构建。

运行时 —— 一个组件如何走到屏幕上

你的 NiceGUI 应用
shadcn.button('Save', variant='outline') —— 纯 Python，普通的 NiceGUI 布局
▼工厂调用
nicegui_shadcn/elements/*.py
工厂 + ShadcnElement：classes= 经 cn() 合并（tw‑merge，调用者优先）· class 字符串写在 Python 常量里
▼Element / ValueElement
NiceGUI 核心
_props 变成真正的 Vue props（model-value → modelValue）· 事件走 websocket · 页面外壳由 NiceGUI 提供（Quasar + Tailwind 层）
▼导入期
elements/*.vue 由 NiceGUI 的 VBuild 解析
单个根标签 · 只用 Options API · data-<stem> 标记 · 与对应的 .py 一起以 ES module 提供
▼浏览器
Vue 3.5 + reka-ui 原语
共用 NiceGUI import map 里的同一个 Vue · reka-ui.js 经 tree-shaking，vue 保持 external
▼
DOM，落在设计 token 上
<button class="bg-primary …"> 由编译后的样式表解析：--primary、--radius，深色模式经 body.body--dark
theme.py —— 导入时一次性注册
  • /_nicegui_shadcn 静态文件
  • import map 覆盖，让 .vue 脚本能 import 'reka-ui'
  • <link rel="stylesheet"> 引入 shadcn.css —— 真 link 而不是 add_css，避免无样式内容闪烁
theming.py —— 运行期主题
  • set_radius() / set_base_color() 重写 CSS 自定义属性
  • 经 app.on_startup 注入一次（head html 只能追加）
  • 已打开的页面用 run_javascript 把变更经 websocket 重放

构建期 —— 为什么用户什么都不用构建

frontend/tailwind.css
@source 扫描 .py/.vue · @theme inline 暴露 token · source(none)
▶Tailwind v4 CLI
static/shadcn.css 已提交
约 201 kB · 只含组件真正用到的 utilities
▶随 wheel 发布
pip install nicegui-shadcn
用户端没有 node_modules、没有打包器、没有 CSS 流水线
frontend/vendor/reka-entry.js
只 re-export 被封装的那些原语
▶esbuild，--external:vue
static/vendor/reka-ui.js 已提交
约 381 kB，经 tree-shaking 的 bundle
▶+ .vue 模板
poetry build → wheel + sdist
check_dist.py 断言这些产物真的随包发布
npm run build ≈ 250 ms。改了 Python 里的 class 或模板却不重新构建，是发布无样式组件的第一大原因 —— Tailwind 只输出它看得见的东西。

验证 —— 每一层拦截上一层拦不住的问题
